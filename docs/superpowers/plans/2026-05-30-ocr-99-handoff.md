## Current bottleneck — what's blocking 99% @ 95%

### Diagnostic on PokerCraft test (n=718)

| Segment | Count | What it means |
|---|---|---|
| `parse_none` | **135** | Parser returns `hand=None` (overall conf ≤ 0.3 or `_assemble_hand` failed) — **cannot emit at any τ** |
| Parsed + emitted | 583 | Where calibrator decides emit-or-abstain |
| ↳ Correct | 529 | 90.74% precision on emit (Phase 10 baseline number) |
| ↳ Wrong | 54 | Calibrator must reject these to reach 99% precision |
| Calibrator-abstained | 68 | Conf < 0.88 emit_threshold (recoverable if calibrator says so) |

**Math**: 99% precision × 95% recall × 718 = **675 correct emits needed**. Current parsable ceiling = 583. **The 95% recall target is mathematically impossible without parser improvements that recover parse_none hands.**

### Where the 54 wrong emits come from

| Failure mode | Count | % | Why current v2 calibrator can't see it |
|---|---|---|---|
| `board_wrong` | 25 | 46% | No board-classifier features in v2 schema (only `hero_card_conf`) |
| `position_wrong` | 21 | 39% | No position-derivation features; position is binary "assigned or not" |
| `hero_cards_wrong` | 5 | 9% | hero `card_conf` is in features — partially caught |
| `preflop_action_types_wrong` | 3 | 5% | Action-sequence-integrity features absent |

92% of wrong emits = board + position errors → v2 schema is blind to them.

### Calibrator-only operating points on PokerCraft test

| τ | Coverage | Precision | Notes |
|---|---|---|---|
| 0.95 | 3.8% | 100.0% | 25/25 |
| 0.92 | 21.8% | 100.0% | 142/142 |
| 0.729 | 64.5% | 99.05% | **416/420 — matches May 23 ship** |
| 0.660 | 73.7% | 98.12% | 471/480 |
| 0.585 | 79.6% | 97.10% | 503/518 |
| 0.447 | 87.7% | 95.10% | 543/571 |

Best achievable today: **99% @ 64.5%** or **95% @ 87.7%**. Joint 99%@95% unreachable until parse_none ceiling lifts AND/OR v2 schema gains board+position signals.

### ECE-10bin (calibration error)

| Bucket | ECE | Bound | Status |
|---|---|---|---|
| PokerCraft test | 0.135 | ≤ 0.04 | ❌ 3.4x over |
| PokerCraft dev | 0.128 | ≤ 0.04 | ❌ |
| Production test | 0.232 | ≤ 0.04 | ❌ (n=10 noisy) |

Calibration is bad — RF+GB+LR averaging produces scores that don't match empirical accuracy. **Isotonic regression on top would fix this** (standard technique, see [Guo 2017](https://arxiv.org/abs/1706.04599)).

## Brainstorm — every option I considered

### Path B (parser → lift recall ceiling above 81%)

**B1. Active WIN-overlay removal pre-OCR**
- 60 templates harvested in `data/win_overlays/`
- Template-match + alpha-composite "fill back" using inpainting or nearby pixel
- Targets the 50 high-`card_conf` parse_none cases where hero is clean but action box is occluded
- **Estimate**: 1 session, recovers 20-40 hands

**B2. Multi-pass relaxed parsing with `partial=True` flag**
- `_assemble_hand` strict-first; on None, retry with relaxed constraints (allow N missing entries, infer from `preflop_actions` string + position layout)
- Emit with `partial=True`, let calibrator decide
- **Estimate**: 1 session, recovers 30-50, +risk of new wrong emits unless calibrator filter is strong

**B3. Panel-only Gemini cascade for high-card-conf parse_none**
- When `_assemble_hand` returns None but `card_conf > 0.8` (the 50 cases) → send **panel region only** (not full image) to Gemini with the partial OCR as scaffolding ("OCR saw X, Y, Z; fill the gap")
- Cheaper than current full-image Gemini fallback
- **Estimate**: 1 session, recovers most of the 50 high-card-conf cases; small API cost

**B4. End-to-end Pix2Struct fine-tune on 7183 corpus**
- Pix2Struct designed for screenshot→structured-output; beats Donut by 9-53 points on layout tasks
- 7183 (image, JSON) pairs is a real fine-tune size
- Replaces region detection + table parser + panel parser with a single model
- **Estimate**: 3-5 sessions, training run ~hours-days on GPU. **Highest ceiling potential.** Risk: production latency, unknown gains.

**B5. VLM-primary via Qwen2.5-VL / Qwen3-VL fine-tune**
- Qwen3-VL 235B exceeds 95% on KIE benchmarks; 8B fine-tune approaches it
- Local deploy (GPU required) avoids per-call Gemini cost
- **Estimate**: 3-4 sessions. Similar profile to B4.

**B6. Super-resolution preprocessing (HAT / Swin-SR / Real-ESRGAN)**
- 2× upsample action-box crops before OCR; 2025 research shows meaningful gains on small text
- Helps action OCR (small text); less help for board cards (already 120px)
- **Estimate**: 1-2 sessions, modest gains

### Path C (calibrator/features → reduce wrong emits)

**C1. Board pipeline features → schema v3**
- New features: `board_classifier_min_conf`, `board_top2_margin_min`, `board_raw_vs_masked_disagree_count`, `board_card_count_vs_street_mismatch`
- Requires `n8_parser` to surface `board_card_details` (currently only `hero_card_details`)
- **Targets**: 25 board_wrong emit errors (46% of current wrong emits)
- **Estimate**: 1 session

**C2. Position pipeline features → schema v3**
- New features: `position_derivation_source` (button / blinds / preflop_count / fallback), `position_consistency_count`, `hero_seat_y_normalized`, `blind_pay_consistent_with_position`
- Requires `_assemble_hand` to expose which signal assigned hero_position
- **Targets**: 21 position_wrong emit errors (39%)
- **Estimate**: 1 session

**C3. Cross-field consistency features (derivative)**
- `action_count_vs_position_count_mismatch`, `stack_sum_pot_consistency`, `pre_loss × card_conf` interaction
- Pure feature engineering, no parser changes
- **Estimate**: < 1 session

**C4. Better CardCNN v3 (the proper approach this time)**
- May 28's v3 with overlay augmentation regressed (`card 0.962` < v2 `0.967`) because 41-px hero crops can't absorb occlusion noise
- Alternative levers that have NOT been tried:
  - **Hard-negative mining** on the 54 calibrator-flagged wrong emits + tough abstains
  - **Focal loss** weighted on confused rank pairs (4/9 is known worst)
  - **Distillation from board cards** — board crops are ~120px (3x larger), train hero head with board predictions as soft targets
  - **Test-time augmentation** (multi-scale predict, average)
  - **Multi-resolution backbone** input
- **Estimate**: 2 sessions if pursued; high uncertainty on gains

**C5. Calibrator architecture improvements**
- **Isotonic regression on ensemble output** — standard ECE fix, cheap, almost certain win for the 0.135 ECE problem
- **XGBoost / LightGBM** instead of sklearn GBM — better tuning surface
- **Conformal prediction reject-option** ([ICLR 2025](https://arxiv.org/abs/2506.21802)) — distribution-free guarantee on precision at chosen reject rate; cleaner than τ-search
- **Meta-learner stacking** instead of plain averaging
- **Estimate**: 1 session for isotonic + conformal; +1 for XGBoost swap

**C6. Per-distribution calibrator (router)**
- PokerCraft pos_rate = 0.87, production_v1 pos_rate = 0.50 — distributions are very different
- Train one calibrator per distribution; classifier-router picks based on image features (table theme, sticker presence, etc.)
- **Estimate**: 2 sessions; depends on production_v1 corpus eventually growing

**C7. Active learning loop**
- After D-a ships, log production 0.45–0.85 score hands → human review (via Phase 11.F dump) → grow corpus → monthly retrain
- Already half-built (`production_inference_dump.py` exists)
- **Estimate**: pipeline + cron; ongoing

## Recommended execution order

### Phase 11.D-a (Quick wins, 1 session) — **start here**

Goal: close the calibrator-precision gap without parser changes. Lift 99% precision coverage from 64.5% to ~75-80% and fix ECE.

1. **C1: Board feature surfacing + features**
   - Modify `scripts/ocr/table_parser.py:parse_table` to surface `board_card_details` (parallel structure to `hero_card_details`); requires running CardCNN on board crops with same raw/masked arbitration
   - Add to v3 schema: `board_min_conf`, `board_top2_margin_min`, `board_raw_vs_masked_disagree`, `board_count_vs_street_mismatch`
   - Update `_calibrator_features_v3` (new function, keep v2 as fallback per `OCR_CALIBRATOR_VERSION`)

2. **C2: Position feature surfacing + features**
   - Modify `_assemble_hand` (n8_parser.py) to record which signal won position assignment; expose via diagnostics
   - Add: `position_source_one_hot`, `position_consistency_count`, `hero_seat_y_norm`, `blind_pay_consistent`

3. **C5: Isotonic regression on top of ensemble**
   - Add isotonic fit step at end of `train_calibrator_v2.py`; save as `isotonic_v2.joblib`
   - `CalibratorScorer.score()` applies isotonic transform to averaged RF+GB+LR output
   - **Expected**: ECE 0.135 → < 0.04

4. **Re-dump train+val+test with v3 features**, retrain, re-evaluate.
5. **Acceptance for D-a**: precision @ 80% coverage ≥ 99%, ECE ≤ 0.04.
   - If yes → move to D-b. If no → C3/C4 before D-b.

### Phase 11.D-b (Recall ceiling lift, 1-2 sessions)

Goal: recover 50+ parse_none cases, lift recall ceiling 81% → 89-92%.

1. **B1: Pre-OCR overlay removal** — template-match WIN stickers from `data/win_overlays/`, inpaint, re-OCR action boxes
2. **B2: Multi-pass relaxed parser** in `_assemble_hand` — emit with `partial=True` for relaxed parses
3. **B3: Panel-only Gemini cascade** for high-card-conf parse_none (`card_conf > 0.8` and `_assemble_hand` returned None)
4. New `partial_parse` boolean feature in v3 schema
5. Re-dump + retrain + re-evaluate
6. **Acceptance for D-b**: total emit candidates ≥ 650 (i.e. ≥30 parse_none recovered) AND calibrator can still hold 99% precision at the new operating point

### Phase 11.D-c (Architecture rewrite, 3-5 sessions) — **only if D-a + D-b can't close to 95%**

1. **B4 or B5**: choose Pix2Struct fine-tune (open-source, custom training pipeline) vs Qwen-VL fine-tune (more parameters, less plumbing)
2. Set up training: 5750 train + 715 val records → (image_path, ground_truth_json) pairs
3. Inference benchmark against current pipeline on test bucket
4. If reaches 95%+ recall AND production latency acceptable → consider replacing region-based pipeline OR using as second-stage verifier
5. **Acceptance for D-c**: joint 99%@95% gate passes per original plan exit criteria

### Phase 11.F (Human-in-the-loop, parallel to all of above)

1. Run `python scripts/production_inference_dump.py --tau 0.99 --out data/production_inference_<date>`
2. User reviews `data/production_inference_<date>/predictions.jsonl` against `images/<hand_id>.png`
3. Promote correct ones via `python scripts/snapshot_test.py --set-expected <hand_id> '<json>'`
4. Re-run `data/cards_v2/production_v1/` harvest (`scripts/_tmp.py` template in the worktree's history) to grow corpus
5. Periodic retrain to lift production_v1 bucket from spot-check to real test bucket

## Don't repeat these mistakes (from Phase 10 + May 28)

1. **Don't retrain CardCNN v3 via overlay augmentation.** Two attempts (`p=0.70`, `p=0.30`) regressed because 41-px crops can't absorb occlusion noise. Use C4 alternatives instead (hard-negative mining, focal loss, distillation).
2. **Don't ship τ-only calibration.** τ-tuning can't reach 99%@95% — May 28 confirmed this. The RF+GB+LR ensemble is required, and additional features are required beyond v2 to close further.
3. **Don't lower the ship gate.** The user explicitly chose to maintain 99%@95% rather than accept the 99%@65% May-23-level baseline.
4. **Don't try to grow `data/cards_v2/production_v1/` corpus via Gemini agreement.** The 7183-hand `data/pokercraft_corpus/` already exists with HH ground truth — that's the primary corpus. The 62-hand Telegram bucket is a secondary distribution-drift spot-check.
5. **Don't change `confidence_gate.py`'s default `emit_threshold` independently.** The calibrator path (`evaluate_with_calibrator`) is the gate; the legacy `emit_threshold=0.88` only matters for backward compatibility when no v2 calibrator is loaded.
6. **Don't trust a single-bucket validation.** Always evaluate joint pokercraft_test ∪ production_test (even though production_test is n=10) to surface distribution-shift problems early.

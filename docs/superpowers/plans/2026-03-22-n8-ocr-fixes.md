# N8 OCR Pipeline Fixes

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the 4 major issues in the N8 OCR pipeline: speed (13.7s → <3s), missing hero_hand, missing postflop streets, missing effective_bb.

**Architecture:** Replace Tesseract with EasyOCR (GPU-accelerated, batched), simplify entry detection to avoid per-entry OCR filtering, fix hero card detection region, and extract effective_bb from panel pot values.

**Tech Stack:** EasyOCR (GPU via PyTorch), OpenCV

---

## Root Cause Analysis

### Issue 1: Speed (13.7s avg)
**Root cause:** `panel_parser._filter_action_entries()` runs 4 Tesseract OCR calls per entry to check if it contains action text. With ~30 entries across 5 columns, that's ~120 Tesseract calls.
**Fix:** Replace Tesseract with EasyOCR (batched, GPU-accelerated). OCR the entire column body at once instead of per-entry. Use entry position/color to classify, not OCR content.

### Issue 2: hero_hand always empty
**Root cause:** `table_parser._find_hero_cards()` searches bottom center but hero cards are often obscured by WIN badge, avatar overlay, or level indicator. Template matching fails on partially occluded cards.
**Fix:** Don't extract hero_hand from table region at all. Instead, parse it from the Blinds(Ante) column or use the card showdown in the River column result section (the yellow "Wins" entry shows hero's cards). Alternatively, fall back to Gemini for hero_hand only.

### Issue 3: Postflop streets missing
**Root cause:** `detect_entries()` finds entry blobs in Flop/Turn/River columns, but `_filter_action_entries()` does per-entry OCR and filters out entries where OCR can't read action text (common for small or edge-clipped entries). This removes most postflop entries.
**Fix:** Stop filtering by OCR content. Trust color-based detection (yellow=hero, white=opponent). OCR each entry once (not 4x) to get action text. If OCR fails, use heuristics (entry with BB amount = Bet/Call/Raise, entry without amount = Check/Fold).

### Issue 4: effective_bb missing
**Root cause:** `_find_player_stacks()` tries to OCR colored BB text scattered around the table — unreliable due to avatars, overlays, varying colors.
**Fix:** Don't OCR stacks from table. Instead, infer effective_bb from: (a) hero's stack shown in Blinds column entries, (b) pot progression, or (c) bet sizes in the hand.

- [ ] **Step 2: Rewrite ocr_utils.py with EasyOCR**

Replace Tesseract wrapper with EasyOCR. Key changes:
- Lazy-initialize a global EasyOCR reader (loads model once)
- `ocr_region(image)` → returns list of `(text, bbox, confidence)`
- `ocr_full_image(image)` → batch OCR entire image, returns all detected text with positions
- Remove `preprocess_for_ocr` (EasyOCR handles preprocessing internally)
- Keep `binarize` for specific use cases

```python
"""OCR utilities using EasyOCR (GPU-accelerated)."""
import cv2
import numpy as np

_reader = None

def _get_reader():
    global _reader
    if _reader is None:
        import easyocr
        _reader = easyocr.Reader(['en'], gpu=True, verbose=False)
    return _reader

def ocr_full_image(image: np.ndarray) -> list[dict]:
    """OCR entire image, return all detected text with bounding boxes.
    Returns: [{"text": str, "bbox": [[x1,y1],[x2,y2],[x3,y3],[x4,y4]], "conf": float}]
    """
    reader = _get_reader()
    if len(image.shape) == 3:
        gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
    else:
        gray = image
    results = reader.readtext(gray)
    return [{"text": r[1], "bbox": r[0], "conf": r[2]} for r in results]

def ocr_region_text(image: np.ndarray) -> str:
    """OCR a small region, return concatenated text."""
    results = ocr_full_image(image)
    return " ".join(r["text"] for r in results)
```

## Task 2: Rewrite panel_parser — no per-entry OCR filtering

**Files:**

- [ ] **Step 1: New approach for panel parsing**

Instead of detect entries → OCR each → filter, the new approach:
1. `split_columns()` — same as before (5 equal columns)
2. For each column body, run `ocr_full_image()` ONCE — get all text + positions
3. Use text Y-positions to group into entries (texts at similar Y = same entry)
4. Use entry color (yellow/white) from the original image to classify hero/opponent
5. Match each text group to action pattern: look for Fold/Check/Call/Bet/Raise + optional BB amount + optional position badge

This eliminates:
- Per-entry OCR (120 calls → 5 calls, one per column)
- `_filter_action_entries` (no longer needed)
- `_detect_position_badge` / `_detect_position_from_context` (position text now found by OCR directly)

## Task 4: Fix effective_bb — infer from hand data

**Files:**
- Modify: `scripts/ocr/n8_parser.py`

- [ ] **Step 1: Infer effective_bb from available data**

Instead of OCR-ing stacks from the table, compute effective_bb from:
1. If hero's BB text is visible in Blinds column (e.g., "BB 1 BB"), check pot sizes
2. Use the first preflop raise size × typical open raise multiplier to estimate stack
3. Or simply set effective_bb from pot values: starting pot / antes ratio gives approximate stack depth

Actually, the simplest reliable approach: **read hero's stack from the table region using EasyOCR**. The stack is displayed as "XX.X BB" in colored text directly under the hero's avatar at bottom-center. This is a focused, small region OCR — should be fast and reliable.

```python
def _find_hero_stack(table_region):
    h, w = table_region.shape[:2]
    # Hero stack text is at bottom center, below the cards
    hero_stack_area = table_region[int(h*0.80):int(h*0.98), int(w*0.25):int(w*0.65)]
    results = ocr_full_image(hero_stack_area)
    for r in results:
        text = r["text"].upper().replace("BB", "").strip()
        try:
            return float(text)
        except ValueError:
            continue
    return None
```
